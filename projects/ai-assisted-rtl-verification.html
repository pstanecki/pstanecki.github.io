AI-Assisted RTL Verification

In progress · SystemVerilog / Python

Building an RTL verification copilot and exploring how retrieved hardware examples influence the LLM-assisted verification process

I’m building a RAG tool that searches through RTL designs and testbenches for relevant examples, and uses selected context -- if any -- as well as the targeted module to draft a verification plan.

View source on GitHub →

Standard Flowchart

The SystemVerilog in the current index contains 20 chunks worth of code. Small modules are just left as is, given the simplicity of the design. Larger sources are split while considering the structure of the language (blocks). A FIFO design exists within the files of the project but outside of the index, to test behaviors on unrelated hardware.

I picked the FIFO for its distance from the AES algorithm implementation, and really hope to significantly expand both what I have indexed and what's available to me to target.

Next steps

I want to expand the indexed modules, and target a variety of modules for verification. I'm looking to see the influence a retrieved example has on the generation of the verification plan, and then eventually start prompting testbench generation.

I would also wish to expand on the chunking process, as it doesn't account for all SystemVerilog syntax and structure, and modules that make more use of what the language has to offer can't be chunked meaningfully as is.
